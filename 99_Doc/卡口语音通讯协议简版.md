# 卡口语音通讯协议简版

串口参数为 **9600 bps、8N1**。帧首字节为设备 ID，默认 `0x01`，可设置。

| 方向 | 帧格式 | 帧尾 |
| --- | --- | --- |
| 主机 → 设备 | ID(1) + 功能码(1) + 长度(2) + 数据(N) + 校验(2) + 帧尾(1) | `0x9F` |
| 设备 → 主机 | ID(1) + 功能码(1) + 长度(1) + 数据(1) + 校验(2) + 帧尾(1) | `0xAF` |

- 括号内为字节数。长度只计算数据区。请求长度高字节在前，应答长度固定为 `0x01`。
- 校验为数据区各字节的累加和，取低 16 位，高字节在前。地址、功能码、长度和帧尾不参与校验。
- 应答功能码与请求相同。原协议各命令通常用 `0xFF` 表示成功、`0x00` 表示失败。查询地址时，应答数据为设备当前 ID。

| 功能码 | 命令 | 请求数据 |
| --- | --- | --- |
| `0xF0` / `0xF7` / `0xF8` | 设置语音条目 1 / 2 / 3 | GBK，联调上限 400 字节 |
| `0xF1` / `0xF9` / `0xFA` | 设置滚屏条目 1 / 2 / 3 | GBK，联调上限 200 字节 |
| `0xF2` | 设置或查询设备 ID | 1 字节。设置时为新 ID，查询时帧首 ID 和数据均为 `0xFF` |
| `0xF3` | 设置 PIR 开关 | 1 字节，`0xFF` 开启、`0x00` 关闭 |
| `0xF4` | 设置播报次数 | 1 字节，0～16 |
| `0xF5` | 设置屏幕显示次数 | 1 字节，0～16 |
| `0xF6` | 触发或停止播报 | 1 字节，0 停止，1～3 启动对应条目 |
| `0xFB` | 设置 PIR 触发时的播报条目 | 1 字节，1～3 |

命令数据不合规，或地址、功能码、帧结构可识别但校验和错误时，回 `0x00`。帧结构或帧尾错误、地址不匹配时不应答。

`0xF2` 设置地址时用旧 ID 回包，发送成功后启用新 ID。查询返回当前 ID。地址随后保存到 QSPI；没有有效配置时默认 `0x01`。

- `0xF0` / `0xF7` / `0xF8` 将文本写入 RAM 对应条目，写入成功回 `0xFF`，不会立即播报。没有有效配置时，三条文本为空。
- `0xF4` 设置后续播报的全局次数，没有有效配置时默认一次。`0` 和 `1` 都播一次。
- `0xF6` 数据为 `1～3` 时提交指定条目，条目为空或请求未入队时回 `0x00`。数据为 `0` 时提交共享播放器停止请求。`0xFF` 表示请求已入队，实际播放或忙时拒绝以播放器日志为准。
- `0xF1` / `0xF9` / `0xFA` 将独立字幕写入 RAM 对应条目，写入时不显示；零长度清除该字幕。`0xF6` 启动播报后优先滚动同编号的独立字幕，未设置时仍显示语音原文。
- `0xF5` 设置后续 `0xF6` 和 PIR 触发的全局滚动次数，写入 RAM，没有有效配置时默认一轮。`0` 和 `1` 都滚一轮，`2～16` 按指定轮数滚动，滚完自动清屏。音频和滚屏各按自己的次数结束；`0xF6=0` 可取消并清屏。播报期间更新 `0xF5` 只影响下次入队。
- `0xF3` 和 `0xFB` 分别设置 PIR 开关和条目号，先写入 RAM，没有有效配置时默认开启、条目 1；条目 1 未设置语音时不会播报。开启后，PC10 的下降沿触发选中条目，沿用同编号的语音和字幕，以及 `0xF4`、`0xF5` 的次数。同一轮任务轮询读到的多个沿合并为一次。COMM 接受一次下降沿后，2 秒内的沿不提交播放，也不延长过滤窗口；条目为空或播放器拒绝时不重试。关闭只禁止后续触发。

系统装配时把配置实例和业务回调交给 COMM。COMM 校验请求后传入条目号、文本或次数，根据回调结果回包。回调在 COMM 任务内同步执行，只有它们读写 `checkpoint_config_t`。播放器在入队时复制选中的文本，因此更新条目不会改变已经入队的播放。

设置类命令回 `0xFF` 表示 RAM 已更新。设备在最后一次设置约 250 ms 后将语音、字幕、次数、PIR 设置和设备 ID 一起写入 QSPI LittleFS，再替换 `/checkpoint.cfg`。看到 `Checkpoint QSPI saved` 才表示已落盘；在此之前断电可能恢复上一份配置。开机先读配置再启动 COMM，文件缺失或校验失败时使用默认值。保存失败会打印日志并重试；挂载失败时本次上电仅使用 RAM。

板测示例（设备 ID 为 `01`）：依次发送以下帧，收到 `FF` 应答后再发下一条。下发字幕后，屏幕应显示“请减速”，语音仍播报“注意安全”。

```text
01 F0 00 08 D7 A2 D2 E2 B0 B2 C8 AB 06 02 9F  # 条目 1：“注意安全”
01 F1 00 06 C7 EB BC F5 CB D9 05 07 9F        # 字幕 1：“请减速”
01 F4 00 01 01 00 01 9F                       # 播报一次
01 F5 00 01 03 00 03 9F                       # 滚屏三轮
01 F6 00 01 01 00 01 9F                       # 播放条目 1
01 F6 00 01 00 00 00 9F                       # 播报期间可发送停止
```
