# 远程模块：配置与正常通信

本次实现以现有 E27-D 板测通路为基础，不改 GPIO、UART、DMA 或厂商文件。

## 调用关系与所有权

```text
按键测试 / 后续 RS485 App
    -> remote_modem_app_config_request(id, size)
    -> 独立 remote_modem 任务
    -> remote_modem_service
    -> bsp_remote_modem
    -> E27-D 驱动 / plat_uart
```

4G 任务是 UART 接收、发送、驱动及 Service 的唯一所有者。
RS485 不操作 4G UART，解析协议后提交同一个 App 请求即可。

- App：静态任务、单槽命令队列、请求准入、状态快照、普通 RX 回调和 LED 联动。
- Service：配置/正常两个业务模式，读取、写入、重启及有限恢复的内部步骤。
- BSP：绑定逻辑 UART，映射板级操作/事件与芯片协议，保留正常 RX 原始字节。
- ExternalChip：单条 AT 指令编码、校验、回复及状态文本解析，无 RTOS 依赖。

## 流程及成功标准

启动：等待启动通知 → 稳定 2 秒 → 进入配置模式 → 查询 SIM、IMEI、ICCID、IMSI、
注册 ID、连接状态（不查询 CSQ） → 每项 OK 后将结果存入 RAM → 退出配置模式收到 OK → 正常通信。
如果通知已在 UART DMA 启动前发出，则最多等待 30 秒后主动查询，避免无限等待。

按键配置：接受并复制 16 字节 ID → 停止接受普通发送 → 有界清理当前接收内容 →
进入配置模式 → 逐项设置 → 保存 → 重启收到 OK → 等待启动通知 → 重走启动读取 →
核对读取的 ID 与请求一致 → 退出收到 OK → 报告配置成功、恢复正常通信。

配置项沿用已验证流程：透传、关闭 Modbus/HEX 转换、60 秒心跳 `www.usr.cn`、
请求 ID、TCP 服务器 `62195.cnsh.iot-tcp.com:15000`、关闭副服务器、
已板测的关闭安全选项、开启状态上报、保存及重启。
心跳在 BSP 转换为原有 HEX 命令，Service 持有实际业务内容。

每条指令严格等待 OK；ERROR、超时、查询结果缺失或 ID 回读不一致都不能报告成功。
重启前没收到 OK，即使收到启动通知，也保留本次配置失败的结果。
恢复普通通信不能把失败的配置改成成功。

首次启动允许尚未配置 16 字节注册 ID；对应缓存有效位不置位。
IMEI、ICCID、IMSI 及必要查询的数据格式必须有效，不能仅用一个 OK 代替数据。
网络未连接与“已经退出配置模式”分别记录，正常模式并不保证当前 TCP 已连接。
身份缓存仅在 RAM；业务参数仍由模块的保存指令持久化，未新增 MCU 参数文件。

## 请求与数据接口

`remote_modem_app_init(&modem_io)` 在系统初始化时创建任务；初始化前需完成日志和 LED 初始化。当前装配启用 `echo_test_enabled`，仅测试回传带小写 `test:` 前缀的完整行。
当前按键测试在 `project/src/freertos_app.c` 中，SW4 长按提交固定
`remote_modem_test_id = "kvt9dxr84qrryr1z"`，SW5 恢复普通语音测试，不再提供诊断入口。

`remote_modem_app_config_request(id, size)`：任务上下文、立即返回。
ID 必须为 16 个字母或数字。成功表示请求已接受，实际开始/完成由任务日志及状态区分。
App 和 Service 分别复制到各自固定存储，调用者返回后可复用原始数据。

启动、配置、重启和恢复期间拒绝新配置；一个已接受的请求立即占用准入槽，
不存在连续排队的配置。故障锁定后允许一次明确的新配置请求，作为人工重试。

`remote_modem_app_send_request(data, size)`：仅正常模式接受，任务负责实际发送。
最多 256 字节，这是固定内存容量，不是未来协议帧长约定；发送不成功记录
`last_request_error`，业务发送失败同时关闭正常模式并进入恢复。
配置期间不缓存或发送业务数据，不因持续普通 RX 无限推迟进入配置。

`remote_modem_app_status_get()` 与 `remote_modem_app_identity_get()` 读取受短临界区
保护的快照；使用身份字段前检查 `valid_mask`。忙状态同时覆盖已接受、尚未执行的请求。
`last_error` 与失败阶段/步骤记录最近流程错误，恢复后仍可查询；新的配置清除旧错误。

普通 RX 可在初始化时注册 `remote_modem_app_io_t.receive` 回调。
回调在 4G 任务执行，数据仅在回调期间有效，不得阻塞或直接调用驱动/Service。
当前业务协议未定义，测试装配未注册业务回调，不另开业务 FIFO。
正常 RX 计数并抓取前 20 块 HEX/ASCII，每块最多显示 64 字节；仅测试消息进入回传。
配置 RX 只用于解析回复，不交付普通数据回调。
当前沿用模块启动/连接状态文本观察，完整业务协议还需定义控制文本与业务数据的分流。

## 超时、恢复及内存

- 发送 500 ms，单条回复 3000 ms，重启通知 30 s，整个流程 120 s。
- 普通切入配置清理阶段 100 ms；错误恢复需 3 s 接收静默，最多等 30 s。
- 每次失败最多尝试一次：清理旧数据 → 重新进入 → 确认退出 → 重新读取 → 确认退出。
  再次失败进入 FAULT，不无限重试，不臆测复位脚极性。
- 发生真实模块启动通知时可重新启动读取；通知不会代替原命令的 OK。
- 任务每 10 ms 轮询，与原按键任务同为最低任务优先级，使用已开启的时间片调度。
  阻塞 UART 发送不会独占更高优先级，音频任务和定时器保持原配置。
- 任务栈静态分配 1024 words（4 KiB），命令单槽及 RX 256 字节缓存也为静态所有权。
  BSP 最大心跳编码缓冲为 256 字节，芯片命令栈缓冲为 320 字节。
- 每 10 s 输出 4G 任务栈高水位；按键提交时同时输出原按键任务高水位。
  必须根据板测配置、恢复、普通 RX 负载下的最小余量确认容量。

## 可重复验证

根目录 `tests/` 下的主机集成测试、模拟 RTOS 头文件和运行脚本已删除，不影响 MDK 固件工程。后续修改以 Keil 编译和可重复板上验收验证；E27-D 驱动目录内的独立测试仍保留。

板上验收：

1. 启动日志显示读取完成并进入正常模式，检查 RAM 身份缓存和连接指示灯。
2. 启动查询时 SW4 长按被拒绝；进入正常后再次长按，接受并开始配置。
3. 配置期间再次长按被拒绝，业务发送返回 BUSY。
4. 保存、重启、读取新 ID、退出全部成功后才出现配置完成日志。
5. 若重启没有返回 OK，必须保留失败日志，不能把启动通知当成功回复。
6. 检查两个任务的栈高水位，并在音频播放同时配置时检查播放连续性。

用户已确认模块链路和服务器双向通信通路可用。板上日志观察到 4G 任务栈最低剩余 572 words（2288 字节），仅代表已执行测试路径，配置/恢复和并发负载仍需进一步覆盖。默认只编译，不烧录。

## 当前测试协议与分层复核

平台发送以小写 `test:` 开头、LF 结束的完整行，MCU 原样回传；CRLF 原样保留。
最大 256 字节含前缀和换行；超长行丢弃至换行；不完整行连续 2 秒无数据则清空。
支持前缀拆包和多行粘包，配置/恢复期间清空测试组帧状态。其他行和模块状态通知不触发回传。
平台不要自动回显回复。正式协议接入后关闭测试开关并替换测试处理。

分层复核：

- `project/` 的模块入口仅调用 App 初始化和配置请求，没有直达模块 BSP/UART/驱动。
- App 唯一责任任务通过 Service 进行配置、轮询、正常发送；不引入 E27-D 类型和 AT 命令。
- App 读取 Service 已公开状态和身份数据，不修改 Service 内部流程状态。
- Service 持有业务步骤和有限恢复，无 RTOS、板级 UART 实例或芯片驱动依赖。
- BSP 实现负责芯片结果、事件和命令的显式映射；公共头文件只提供通用能力类型。
- E27-D 驱动只依赖标准 C 和注入的 IO 回调，不反向依赖平台和业务层。
- RTOS 任务、队列和跨任务状态快照由 App 持有；UART、日志、队列调用在临界区外执行。

当前接收边界：模块通知已被驱动解析，但原始字节仍可进入普通 RX 回调。
`test:` 规则只是避免误回传，不是正式业务数据分流。未来需结合协议帧格式处理通知与数据区分，
不在 App 解析芯片 AT 状态文本，不按单次 UART 接收块判定业务帧。
RS485 协议尚未确定，暂不增加协议或任务；当前 SW4 长按继续使用固定测试 ID。
协议确定后由 RS485 App 校验帧并调用 `remote_modem_app_config_request()`，
区分请求接受、忙时拒绝与配置最终结果，不跨层操作 4G 串口。

基础可用阶段清理：取消的 CSQ 查询已从 Service 分支/状态字段及 BSP 操作/报告映射中删除；通用 E27-D 驱动仍保留该指令的编码与解析能力。App 配置、发送、状态和身份读取接口保留，供后续协议使用。旧 remote_modem_config_app/service 已由当前文件替代，工程不再引用旧实现。
