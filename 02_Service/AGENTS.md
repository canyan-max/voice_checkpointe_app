# Service 层规则

本目录负责可复用业务状态机和数据处理，同时继承仓库根目录 `AGENTS.md`。

- 禁止包含 FreeRTOS 头文件，禁止创建任务、队列、信号量、通知或调用调度延时。
- Service 接口必须使用业务通用名称；允许复用 BSP 的通用能力类型，但不得暴露 `vtx316_*`、AT32 厂商类型、GPIO/UART 实例等实现细节。
- Service 调用 BSP 后负责把板级结果解释为播放器业务状态；具体芯片事件和状态不得继续穿透到 App。
- 播放器 Service 统一持有 IDLE、准备、各类播放、紧急和错误状态，并在这里执行音源互斥判断。
- Service 不拥有外部触发队列；调用方负责调度，Service 函数负责一次确定、有限时的处理。
- MP3 数据来源只能通过 `audio_data_source_t` 的 `open/read/seek/close` 接口接入，不得绑定 FatFs、SD、QSPI 或 USB 的具体实现。
- 状态转换、数组边界、数据长度和硬件调用失败路径必须显式处理；错误后是否可重试必须有确定状态。
