# HUB12 显示与 GT20L16S1Y 字库接入总结

> 建立日期：2026-09-17  
> 当前阶段：HUB12扫描核心与显示生命周期已初步收敛  
> 下一目标：板测VTX316字幕联动和PC9开关，随后接入GT20L16S1Y

本文记录已经通过板上显示确认的事实、当前代码边界，以及后续接入 GT20L16S1Y 的建议方案。详细硬件调试过程和验收步骤见 `.agents/hub_vendor_screen_plan.md`。

## 1. 当前已实现的功能

- 本板 HUB12 接口及两片 74HCT245 已接入 Board、Platform GPIO 和 BSP。
- `HUB_OE245` 用于两片245的总线接通与隔离，`HUB_OE` 用于屏幕扫描消隐与显示。
- 已复现厂家屏的1/4扫描：A/B 在4个扫描相位间循环，C/D保持固定状态。
- 每个扫描相位发送256 bit，R1/G1输出相同数据，按厂家低有效数据极性运行。
- 当前以5 ms为一个行相位，4个相位约20 ms，完整画面刷新率约50 Hz。
- 固定显示和滚动链路均已在实屏上工作。
- 单字“注”已经验证字形完整。
- “注意安全”4个16×16字模已加入当前测试，按厂家默认方向从下往上逐点滚动。
- PC9已确认为低电平开启屏幕电源、高电平关闭屏幕电源。
- GPIO初始化阶段将PC9置高；显示App初始化后默认断电且不启动扫描。
- 正式显示App提供静态、滚动两种显示模式以及统一的 `show/hide` 生命周期。
- `hide()`按消隐、停止扫描、隔离245、PC9断电的顺序收尾。
- VTX316语音指示统一启动字幕和LED_OUT_R/B：红灯先亮，红/蓝每5秒交替；正常播放结束后等待当前轮字幕完整滚出，随后由同一个完成事件关屏并熄灭两灯。启动失败、命令拒绝、轮询异常、手动停止和紧急打断仍立即全部关闭。
- Keil完整编译结果为0 error、0 warning。

当前已经形成仅针对厂家HUB12屏的基础显示框架，并已接入VTX316生命周期。GT20L16S1Y字模输入以及HUB08/HUB75驱动尚未实现。

## 2. 硬件职责

### 2.1 MCU输出信号

| 信号 | 当前职责 |
| --- | --- |
| `HUB_R1`、`HUB_G1` | HUB12两路相同的串行点阵数据 |
| `HUB_SCK` | 将数据逐bit移入屏幕移位寄存器 |
| `HUB_LAT` | 将本次串行数据锁存到屏幕输出寄存器 |
| `HUB_A`、`HUB_B` | 选择1/4扫描的当前相位 |
| `HUB_OE` | 行切换期间消隐，锁存和选行后允许显示 |
| `HUB_OE245` | 接通或隔离两片74HCT245的所有输出 |

### 2.2 74HCT245

74HCT245不保存画面，也不产生滚动。它们只负责：

- MCU侧3.3 V到屏幕侧电平的转换和缓冲；
- 提高信号驱动能力；
- 在上电、停机或异常时通过 `HUB_OE245` 隔离整组输出。

### 2.3 HUB12屏幕

屏幕内部移位寄存器接收串行数据，锁存器保存当前扫描相位的数据，A/B选择当前被点亮的扫描组。MCU必须持续刷新，停止刷新后不能把它当作具有完整帧存储能力的普通显示器。

## 3. 两套时间机制

当前显示由“扫描刷新”和“动画更新”两个不同时间尺度组成：

```text
扫描刷新：每5 ms切换一个A/B相位
    4相位 × 5 ms = 20 ms/帧 ≈ 50 Hz

动画更新：每5个完整帧移动一个点
    5帧 × 20 ms = 100 ms/滚动步骤
```

因此一个滚动位置会被稳定刷新约5个完整画面。扫描频率决定是否闪烁，动画周期决定文字移动速度，两者不应混为一个参数。

厂家 `shuaxin()` 只执行扫描刷新，不负责计算滚动内容。真正的滚动来自对 `hubram` 内容的周期性重算。

## 4. 厂家数据布局

### 4.1 单字字模

一个汉字为16×16点阵：

```text
16 × 16 = 256 bit = 32字节
```

厂家字模以两个连续的16字节块保存。当前已经确认，必须按厂家原生布局参与移位，不能直接假设为常规的 `framebuffer[y][x]`。

### 4.2 显示缓存

厂家使用：

```c
uint8_t hubram[8][16];
```

总容量为128字节，恰好等于4个16×16汉字：

```text
8 × 16 = 128字节
4字 × 32字节 = 128字节
```

但 `hubram[8][16]` 是扫描打包格式，不是按屏幕坐标自然排列的二维图像。厂家发送顺序还包含块倒序和列组倒序：

```c
hubram[7 - source_block][row + (3 - group) * 4]
```

之前按常规Y坐标直接移动时出现字形不完整，根因就是错误解释了该布局。

## 5. 厂家滚动原理

屏幕可同时显示4个字，厂家准备5个字位作为滑动窗口：

```text
4个可见字位 + 1个即将进入的字位 = 5个暂存字位
```

相邻字节通过移位和按位或拼接：

```c
output = (current >> shift) |
         (next << (8 - shift));
```

因为一个字的运动方向有16个点，而一个字节只有8 bit，所以分两段处理：

- `step=0~7`：当前8 bit块和下一个8 bit块拼接；
- `step=8~15`：切换到后一个8 bit块并继续拼接。

完成16步后，相当于移动了一个完整的16点字位，再推进粗粒度的字符阶段。

当前“注意安全”的逻辑窗口为：

```text
阶段0：空 空 空 空 注
阶段1：空 空 空 注 意
阶段2：空 空 注 意 安
阶段3：空 注 意 安 全
阶段4：注 意 安 全 空
阶段5：意 安 全 空 空
阶段6：安 全 空 空 空
阶段7：全 空 空 空 空
阶段8：空 空 空 空 空
```

相邻阶段之间还有16个逐点过渡帧，所以显示效果不是整字跳动。

屏幕本身没有“滚动命令”。软件不断生成位置略有不同的画面，肉眼将连续画面识别为滚动。这属于逐帧软件动画。

## 6. 当前代码边界

```text

    ├─ 统一编排VTX字幕和LED_OUT_R/B生命周期

    └─ 异常、停止和紧急打断时统一立即关闭

    ├─ 独立管理LED4_RUN心跳

    ├─ 持有FreeRTOS静态软件定时器，显示期间每5 ms刷新一次
    ├─ 提供静态/滚动显示模式
    └─ 管理show/hide和空闲停扫

02_Service/hub_display_service
    ├─ 当前固定“注意安全”字模
    ├─ 管理16步细位移和字符粗位移
    └─ 生成BSP需要的扫描数据

    ├─ 绑定本板HUB GPIO资源
    ├─ 管理PC9低有效屏幕电源

    ├─ 控制OE、LAT、A/B时序
    └─ 负责初始化、启动、扫描和安全断电

    └─ 将Board GPIO资源映射到AT32端口和引脚
```

当前测试没有额外分配厂家原版160字节 `ch3` 缓存。Service根据字符阶段和暂存字位即时判断应读取哪个固定字模，减少了一份重复RAM。

## 7. GT20L16S1Y接入目标

GT20L16S1Y的目标不是参与屏幕扫描，而是替代当前硬编码字模数组：

```text
输入文本/字符编码
        ↓
GT20L16S1Y读取16×16字模（每字32字节）
        ↓
5字滑动窗口或字模缓存
        ↓
16步滚动拼接
        ↓
HUB扫描格式
        ↓
HUB12 BSP持续刷新
```

GT20L16S1Y只提供“某个字符对应哪些点亮”，HUB12驱动负责“如何把这些点持续显示到屏幕上”。两部分应保持解耦。

## 8. 建议的GT20L16S1Y分层

### 8.1 ExternalChip

建议建立：

```text
06_Component/ExternalChip/GT20L16S1Y/
    gt20l16s1y.c
    gt20l16s1y.h
```

职责：

- 通过初始化时注入的总线读写回调访问芯片；
- 实现芯片命令、地址换算和原始数据读取；
- 校验输入编码、字模尺寸、地址范围和读取长度；
- 输出固定32字节的16×16原始字模；
- 不依赖AT32厂商库、Board资源、BSP、Service或FreeRTOS。

具体串行接口、命令字、时钟上限和GB2312地址算法必须以GT20L16S1Y正式资料为准，不能只照搬厂家示例中的bit-bang代码。

### 8.2 BSP字库能力

建议由BSP负责：

- 绑定本板实际SPI/GPIO资源；
- 持有唯一GT20L16S1Y器件实例；
- 将芯片私有错误和类型转换为板级通用结果；
- 对Service提供通用的16×16字模读取能力。

BSP公共接口不应暴露GT20L16S1Y私有context、命令字或寄存器类型。

### 8.3 Service显示处理

Service负责：

- 接收需要显示的字符序列；
- 管理当前字符位置和5字滑动窗口；
- 将32字节字模按厂家原生布局参与16步拼接；
- 生成128字节扫描内容；
- 处理文本结束后的空白离场和循环/停止策略。

Service继续禁止持有任务、队列、通知或FreeRTOS延时。

### 8.4 App调度

App负责：

- 接收4G、RS485或其他业务产生的显示请求；
- 决定覆盖、排队、循环、停止和显示速度；
- 持有后续显示任务、队列或定时对象；
- 选择合适的非实时上下文预取GT20字模。

## 9. GT20接入时最重要的实时性约束

禁止在当前5 ms软件定时器回调中直接读取GT20L16S1Y。

原因：

- 外部字库读取可能是阻塞SPI或GPIO模拟时序；
- 字库读取时间会延迟FreeRTOS Timer Service任务；
- 扫描延迟会造成屏幕闪烁、错行或亮度变化；
- 同一Timer Service任务上的其他软件定时器也可能被拖延。

建议采用“预取字模 + 扫描只读缓存”的方式：

```text
非实时上下文：读取下一个字模并写入待用缓存
                         ↓
完整帧边界：原子切换或复制到活动窗口
                         ↓
5 ms刷新路径：只读取已经准备好的RAM，不访问GT20
```

初版可静态分配5个字模缓存：

```text
5 × 32字节 = 160字节
```

这点RAM开销可换取明确的所有权、稳定刷新和简单边界。后续如需长文本，不应把整段文本全部展开为点阵，只需保留当前4字和下一个待进入字。

## 10. 建议的字模公共格式

首版可以固定为：

```c
#define FONT_GLYPH_16X16_BYTES 32U

typedef struct FONT_GLYPH_16X16_T
{
    uint8_t data[FONT_GLYPH_16X16_BYTES];
} font_glyph_16x16_t;
```

需要先确认GT20L16S1Y输出的32字节排列是否与厂家当前固定数组完全一致：

- 如果一致，字模可直接进入现有滚动拼接；
- 如果只是位序、上下8行或列顺序不同，应在字库/BSP边界集中转换；
- 禁止把转换补丁散落在HUB扫描循环中。

`font_glyph_16x16_t` 应表达通用字模能力，不带GT20芯片名称。字符编码接口在确认产品实际使用GB2312、GBK或Unicode转换链路后再定，不提前混用编码。

## 11. GT20接入前必须确认

1. GT20L16S1Y正式数据手册和准确芯片型号后缀。
2. 本板原理图中的供电、电平、片选、时钟和数据引脚。
3. 资源表中分配的SPI实例或GPIO模拟接口。
4. 是否与SD卡、QSPI或其他器件共用总线，以及片选和互斥方式。
5. 最大允许SPI时钟、上电等待时间和一次32字节读取时长。
6. 当前产品文本实际采用GB2312、GBK还是其他编码。
7. 中文16×16字模的地址换算规则和缺字行为。
8. ASCII、数字和标点采用8×16还是统一扩展为16×16。
9. GT20输出字模的位序是否与当前厂家固定数组一致。
10. 读取失败时显示空白、替代符还是保留上一字的产品策略。

## 12. 推荐实施顺序

### 阶段1：GT20单字读取

- 只读取“注”字的32字节。
- 将读取结果与当前硬编码数组逐字节比较并打印首个差异位置。
- 不接入滚动，不在刷新回调内读芯片。

完成标准：32字节内容一致，或者明确得到唯一、固定的格式转换规则。

### 阶段2：替换固定“注”字

- 保留当前单字滚动路径。
- 将字模来源从常量数组切换到GT20预取缓存。

完成标准：显示形状、方向和单字滚动与硬编码版本一致。

### 阶段3：读取“注意安全”

- 顺序读取4个字符。
- 填入静态字模缓存。
- 复现当前已经通过的4字滚动效果。

完成标准：与当前固定数组版本视觉效果一致，连续运行无闪烁和错字。

### 阶段4：通用短文本

- 明确编码和文本长度边界。
- 只预取当前窗口和下一个字，不展开整段点阵。
- 加入结束、循环、停止和新内容切换策略。

完成标准：输入不同短文本无需修改HUB扫描代码。

### 阶段5：业务联动

- 从4G、RS485或其他正式事件提交显示请求。
- 将当前 `hub_display_test_app` 收敛为正式显示App。
- 定义忙时覆盖、排队和优先级规则。

## 13. 当前暂不处理

- HUB08三色和HUB75全彩显示。
- RGB灰度、亮度bitplane和复杂PWM。
- DMA自动移位。
- 任意字号、比例字体和图形绘制。
- Unicode完整字体渲染系统。
- 在5 ms刷新路径中同步读取外部字库。
- 未确认硬件资源前直接移植厂家GT20示例。

## 14. 当前结论

当前已经验证的核心不是“注意安全”这组固定数据，而是完整的数据通路：

```text
32字节厂家格式字模
    → 5字滑动窗口
    → 16步相邻块拼接
    → 128字节厂家扫描布局
    → 4相位、256 bit/相位的HUB12刷新
```

接入GT20L16S1Y后，HUB刷新和滚动算法原则上不需要重新设计，只需要把硬编码的32字节字模替换为可靠、提前读取的字模缓存。实现时最关键的是确认字模位序，并把GT20阻塞读取隔离在5 ms扫描路径之外。
