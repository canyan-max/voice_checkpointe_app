# HUB 厂家屏调试计划

> 建立日期：2026-09-16  
> 最近更新：2026-09-17  
> 当前阶段：HUB12已联动VTX316生命周期并编译，待板测字幕和PC9开关  
> 首个目标：在本项目 AT32F435 板上稳定驱动厂家配套 HUB12 单色屏

本文记录 HUB 显示接口的已确认事实、厂家样例行为、首版实施范围、验证步骤和后续扩展边界。开始编码前应再次核对本文中的“待确认项”，不得根据厂家 STM32 工程猜测本板 MCU 引脚。

## 1. 信息来源与优先级

发生冲突时按以下顺序判断：

1. 本板正式原理图：确认电气连接、信号方向、电平转换和连接器定义。
2. `99_Doc/voice_checkpoint_resouce_map.xlsx`：确认 AT32F435 引脚分配、初始电平和逻辑资源名。
3. 当前工程配置和实现：确认资源表是否已经落实到 WorkBench 配置、GPIO 初始化和 Board 资源表。
4. 厂家 `LED012` 工程：只用于理解厂家配套 HUB12 屏的扫描参数、数据排列和时序，不作为本板引脚依据。
5. 板上实测和逻辑分析仪波形：用于最终确认 OE 极性、数据极性、显示方向和实际刷新效果。

原理图、资源表和代码不一致时先停止编码，确认并更新资源表，再同步代码。

## 2. 首版范围

首版只调试厂家配套的 HUB12 单色屏：

- 只连接 HUB12 接口。
- 复现厂家固定图案，不先实现文字排版、滚动显示和业务内容。
- 采用厂家屏的 1/4 扫描方式，只使用 A/B 选择扫描行。
- C/D 保持固定安全电平，E 与 HUB12 无关。
- R1/G1 输出相同数据，先复现厂家双数据通道行为。
- 每个扫描相位发送 256 bit，按 MSB first 移位。
- 首轮刷新频率目标约 53 Hz，点亮后再根据闪烁和中断占用调整。
- 首轮保留厂家数据和 OE 极性，通过实屏结果验证，不提前“纠正”厂家行为。

首版不同时支持 HUB08、HUB75，也不建立复杂的多屏运行时选择系统。

## 3. 本板硬件事实

### 3.1 74HCT245

- 两片 `74HCT245PW` 由 `4.8VOUT` 供电，将 MCU 的 3.3 V 控制信号转换为屏幕侧电平。
- 两片 245 的 DIR 均固定接 3.3 V，数据方向固定为 MCU A 侧到屏幕 B 侧。
- 两片 245 的低有效 `/OE` 共用 `HUB_OE245`。
- `HUB_OE245` 通过 R46 上拉到 3.3 V，因此 MCU 尚未接管时两个 245 默认关闭输出。
- SCK 屏幕侧串联 33 Ω 电阻 R22，其他信号没有在该页显示串联电阻。
- 两片 245 均为非反相缓冲，MCU 侧 `HUB_OE` 与连接器侧 `OE` 逻辑电平相同。

### 3.2 两个 OE 信号的职责

| 信号 | 连接位置 | 有效电平 | 职责 |
| --- | --- | --- | --- |
| `HUB_OE245` | 两片 74HCT245 的 `/OE` | 低有效 | 接通或隔离整组 HUB 输出总线 |
| `HUB_OE` | 第一片 245 的 A3，经 B3 输出到连接器 `OE` | 由屏幕类型决定 | 行切换消隐、显示使能和后续亮度 PWM |

运行扫描时不得用 `HUB_OE245` 代替屏幕 `HUB_OE`：

- `HUB_OE245` 只用于上电安全、停机隔离和故障保护。
- `HUB_OE` 用于每行扫描的显示/消隐时序。
- 正常刷新期间 `HUB_OE245` 应保持低电平。

### 3.3 三种连接器能力

| 接口 | 行地址 | 数据通道 | 备注 |
| --- | --- | --- | --- |
| HUB12 单色 | A/B/C/D | R1/G1 | 首版调试目标 |
| HUB08 三色 | A/B/C/D | R1/G1/R2/G2 | 后续支持 |
| HUB75 全彩 | A/B/C/D/E | R1/G1/B1/R2/G2/B2 | 后续支持 |

三种连接器共用 MCU 信号和两片 245，产品运行时按一种屏幕配置驱动。首版测试只接厂家 HUB12 屏。

### Board/Platform 接入前待办

`HUB_OE` 已确认映射到 PC6。当前生成配置已经完成：

- `at32f435_437_wk_config.h` 已生成 `HUB_OE_PC6_PIN` 和 `HUB_OE_PC6_GPIO_PORT`。
- `wk_gpio.c` 已将 PC6 配置为推挽输出，初始输出低电平。
- PC6 不再作为未使用模拟引脚配置。

后续开始 HUB 驱动前还需要：

1. 在 `board_resources.h` 中增加独立的 `BOARD_GPIO_HUB_OE` 资源 ID。
2. 在 `board_at32f435_binding.h` 中绑定 PC6 的端口和引脚宏。
3. 在 AT32 GPIO 实现的配置表中加入 `HUB_OE`。
4. 核对资源数量、枚举边界和所有依赖 Board GPIO 数量的静态表。
5. 板上确认 PC6 初始低电平确实能让厂家 HUB12 屏保持消隐。

在 Board/Platform 接入完成前，应用和 BSP 不应绕过平台层直接操作 PC6，也不得把 `HUB_OE245` 当作 `HUB_OE` 使用。

## 5. 厂家样例提取结果

### 5.1 刷新链路

```text
TIM6 更新中断
  -> HAL_TIM_IRQHandler()
  -> HAL_TIM_PeriodElapsedCallback()
  -> shuaxin()
  -> chuanxing()
  -> GPIO 数据、时钟、锁存和行地址操作
```

### 5.2 定时参数

| 项目 | 厂家配置 |
| --- | --- |
| 系统时钟 | 64 MHz |
| TIM6 Prescaler | 4，硬件实际除以 5 |
| TIM6 Period | 60000，硬件实际计数 60001 次 |
| 行相位刷新频率 | 约 213.3 Hz |
| 4 相位整帧刷新频率 | 约 53.3 Hz |
| TIM6 中断优先级 | 3 |

计算关系：

```text
row_rate = 64 MHz / (4 + 1) / (60000 + 1) ~= 213.3 Hz
frame_rate = row_rate / 4 ~= 53.3 Hz
```

### 5.3 数据和扫描方式

- `hubram[8][16]` 共 128 字节，为厂家特定字模和屏幕级联排列，不是通用二维 framebuffer。
- 每个扫描相位发送 `8 × 4 × 8 = 256 bit`。
- 字节按厂家特定倒序选取，位按 MSB first 输出。
- R、G 两路始终发送相同 bit。
- 只更新 A/B，`hang` 在 0～3 之间循环，属于 1/4 扫描。
- 厂家数据宏命名存在反直觉行为：bit 为 0 时 GPIO 置高，bit 为 1 时 GPIO 置低，说明首轮应按“数据低有效”复现并实测。
- 厂家刷新流程在移位时保持屏幕 OE 为低，锁存和选行后将 OE 置高，说明该样例按“OE 高电平显示”运行。该结论只适用于厂家屏首轮复现，不能直接用于 HUB75。

### 5.4 不移植的内容

- STM32 HAL GPIO 宏、TIM 句柄和中断框架。
- 与 HUB 无关的 UART、TTS、ADC、按键和看门狗业务。
- `led_buf[490]` 等与扫描无关的业务缓存。
- 厂家全局变量命名和无边界保护的缓存访问方式。
- 在同一个定时中断回调中执行其他业务判断的结构。
- 厂家 `eg_en_highton` 控制，不能将其猜测为本板 `HUB_OE245`。

## 6. 建议的软件边界

首版保持简单，但不能把厂家代码直接塞入 `freertos_app.c`：

```text
测试触发/App
   -> 设置测试图案、启动或停止显示
   -> 不参与周期扫描

BSP HUB 显示层
   -> 本板 OE245 安全控制
   -> 厂家屏扫描配置
   -> 启动、停止、提交显示数据

AT32 低层实现
   -> 定时器更新中断
   -> GPIOD HUB 位的快速、受掩码保护写入
   -> 一次中断只刷新一个行相位
```

约束：

- Service 层不持有定时器、中断或 FreeRTOS 对象。
- ISR 中不打印日志，不调用阻塞接口，不做动态内存分配。
- 不在 256 bit 热路径中反复调用通用 `plat_gpio_write()`。
- HUB 快速写入必须使用固定掩码，只更新 HUB 输出位，保护 PD7、PD14 和其他非 HUB 位。
- App 修改显示缓存与 ISR 读取缓存之间必须有明确一致性策略。固定图案阶段可在停扫状态更新；后续动态显示再考虑双缓冲或帧边界交换。
- 首版定时器资源必须在实现前核对，不能占用当前音频、FreeRTOS 时基或其他已配置外设。

## 7. 安全上电和停机时序

### 7.1 初始化

```text
1. HUB_OE245 = 高，隔离两个 74HCT245
2. HUB_OE = 厂家屏消隐电平
3. SCK = 低，LAT = 低
4. A/B/C/D/E = 低
5. 所有数据线 = 熄灭数据电平
6. 清除定时器更新标志并准备首行数据
7. HUB_OE245 = 低，接通总线
8. 启动行刷新定时器
```

屏幕消隐电平必须在实测前保持为可配置项。第一轮按厂家样例假设 `HUB_OE=低` 为消隐、`HUB_OE=高` 为显示。

### 7.2 每行刷新

厂家屏首轮按以下顺序复现：

```text
1. HUB_OE = 消隐
2. 发送本相位 256 bit
3. LAT 产生有效锁存脉冲
4. 更新 A/B 行地址
5. HUB_OE = 显示
6. 行号加一并按 4 回绕
```

### 7.3 停止与异常保护

```text
1. HUB_OE = 消隐
2. 停止刷新定时器并清除中断标志
3. 数据、SCK、LAT、地址回到安全电平
4. HUB_OE245 = 高，隔离输出
```

初始化失败、参数越界或定时器启动失败时都必须进入同一安全停机路径。

## 8. 分阶段实施计划

### 阶段 0：关闭硬件信息缺口

- `HUB_OE` 已确认使用 PC6，生成配置已完成。
- 将 PC6 接入 Board/Platform GPIO 资源，并检查资源表边界。
- 确认厂家屏型号、物理分辨率、模组数量和级联方向。
- 确认测试时只连接 HUB12 屏，HUB08/HUB75 连接器为空。
- 确认选用的 AT32 定时器及其中断优先级不影响 FreeRTOS 和音频 EDMA。

完成标准：原理图、资源表、代码宏三者一致，无待猜测引脚。

### 阶段 1：静态 GPIO 与总线安全验证

- 不启动周期刷新。
- 上电保持 `HUB_OE245=高`。
- 设置 SCK、LAT、A/B、R1/G1 的已知电平。
- 最后拉低 `HUB_OE245`，用万用表或逻辑分析仪确认 245 输出侧电平。
- 单独验证 `HUB_OE` 能切换连接器 OE 引脚。

完成标准：所有信号方向和静态电平与原理图一致，不出现随机点亮或总线冲突。

### 阶段 2：手动移位与固定行验证

- 保持屏幕消隐。
- 输出少量可识别 bit 模式并锁存。
- 固定 A/B 行地址，验证 SCK、LAT、R1/G1 波形。
- 检查每帧恰好 256 个 SCK 有效沿。

完成标准：逻辑分析仪观察到正确的 bit 数、MSB first 顺序和锁存位置。

### 阶段 3：定时扫描厂家固定图案

- 建立一个行相位定时器中断。
- 复用厂家 `hubram[8][16]` 固定图案和索引顺序。
- 从约 213.3 Hz 行相位频率开始，形成约 53.3 Hz 整帧刷新。
- App 只负责一次性启动，ISR 独立刷新。

完成标准：屏幕持续显示固定图案，不滚动、不随机错行、不持续闪烁。

### 阶段 4：根据实屏修正极性和排列

按症状一次只修改一个变量：

| 现象 | 优先核对项 |
| --- | --- |
| 全黑 | OE 显示极性、OE245 状态、屏幕供电 |
| 全亮或背景反色 | R1/G1 数据极性 |
| 行错位或重影 | OE 消隐窗口、LAT 与 A/B 更新顺序 |
| 图案镜像 | bit 顺序或字节发送顺序 |
| 图案分段顺序错误 | 4 个字节组的倒序索引 |
| 明显闪烁 | 整帧刷新率、ISR 延迟和显示占空比 |
| 音频异常 | 中断优先级、ISR 执行时间和 GPIO 热路径开销 |

完成标准：极性、方向和扫描参数形成明确配置，不把补丁散落在循环逻辑中。

### 阶段 5：接口收敛和回归验证

- 提供最少的初始化、启动、停止和固定图案更新入口。
- 删除临时逐 bit 日志和无用诊断分支。
- 保留必要的错误返回、参数边界和安全停机处理。
- 编译达到 0 error、0 warning。
- 同时运行现有音频播放进行回归，确认 MP3 无 underrun、VTX316 不受影响。

完成标准：厂家 HUB12 屏可重复上电点亮，连续运行稳定，并且不破坏现有音频功能。

## 9. 首轮测试图案

建议按以下顺序验证：

1. 全灭：验证 OE 和熄灭数据极性。
2. 全亮：验证两个数据通道和所有扫描行。
3. 单点或单列：验证移位方向和 256 bit 边界。
4. 交替位 `0xAA/0x55`：验证时钟和相邻列。
5. 厂家 `hubram` 字模：验证厂家特定字节排列。

每个图案至少观察：

- 上电瞬间是否随机闪亮。
- 行切换是否出现鬼影。
- 显示方向是否镜像或倒置。
- 运行 10 分钟是否发生漂移、卡屏或明显闪烁。
- 同时播放 MP3 时是否出现音频 underrun。

## 10. 诊断信息和测量点

允许在启动、停止和错误路径记录低频日志：

- 选用的屏幕 profile。
- 行相位频率和整帧频率。
- 每行 bit 数。
- 当前 OE 和数据有效极性。
- 定时器启动结果、停止结果和异常计数。

ISR 中禁止逐行或逐 bit 打印。刷新频率和波形应通过逻辑分析仪测量：

- SCK 数量和周期。
- LAT 脉冲位置及宽度。
- OE 消隐窗口。
- A/B 相位顺序。
- 一次完整 4 行循环的周期。

## 11. 性能与并发要求

- 一次行中断必须在下一个行周期前完成，并留出足够 CPU 余量。
- 记录 ISR 最长执行时间，不能只看平均时间。
- 不允许 HUB 扫描阻塞 FreeRTOS 调度数毫秒。
- 不允许降低音频 EDMA 中断的实时性。
- HUB 缓存使用静态分配，禁止 `malloc/free`。
- 厂家固定缓存为 128 字节，首版不扩大为全彩多 bitplane 缓冲。
- 后续动态内容需要双缓冲时，再根据 SRAM 使用量单独评估。

## 12. 暂不实现

- HUB08 三色屏和 HUB75 全彩屏。
- 多种屏幕同时连接或同时扫描。
- RGB 灰度、亮度 bitplane 和高刷新 PWM。
- 通用字库、任意字符串排版和复杂动画；当前仅实现厂家固定字模循环左移测试。
- DMA 自动移位。
- 通用二维 framebuffer。
- 屏幕自动识别和运行时热插拔。
- 由业务 Service 直接控制 GPIO 或定时器。

厂家屏稳定后，再根据实际产品屏幕规格讨论公共 HUB 扫描核心、屏幕 profile、framebuffer 和 DMA 是否值得实现。

## 14. 当前结论

本项目先用最小可验证方案复现厂家 HUB12 屏：固定 1/4 扫描、256 bit/行、R1/G1 同数据和约 53 Hz 整帧刷新。厂家工程只提供屏幕行为参考；本板引脚、电平转换和 OE245 安全控制全部以本板原理图和资源表为准。

独立 `HUB_OE` 已确认使用 PC6，并已接入 Board/Platform GPIO 资源。首版使用 FreeRTOS 静态软件定时器，以 5 ms 行周期刷新厂家固定图案，形成约 50 Hz 整帧刷新。固定显示和向左循环滚动已经通过基础显示验证。

厂家 `shuaxin()` 已确认只负责 1/4 扫描刷新，真正的动画位于 `gt20_test()`：使用5个字位的暂存窗口为4个可见字位供数，通过 `dangqianbuzhou=0~15` 对相邻16字节块进行移位拼接。因此 `hubram[8][16]` 不能作为常规二维 framebuffer 解释。上一版按逻辑 Y 坐标移动的诊断出现字形不完整且方向相反，现已移除。

单字“注”的厂家原生滚动已经板测通过，字形完整；经过与屏幕方向对照，保留厂家默认的字位阶段和16步递增方向。“注意安全”四字连续滚动也已初步复现。

当前已将测试App收敛为正式 `hub_display_app`：初始化只创建静态资源，默认PC9高电平断电且不启动扫描；`show()`可选择四字静态显示或厂家滚动；`hide()`先停止刷新并安全关闭HUB总线，再将PC9拉高断电。HUB08/HUB75暂不实现，未来以独立屏幕驱动接入，不在当前HUB12扫描循环中增加未验证分支。

VTX316播放器生命周期已经接入，并由 `voice_presentation_app` 统一编排字幕和LED_OUT_R/B；`audio_playback_app` 不再分别控制灯和屏，`led_indicator_app` 与 `hub_display_app` 也不再互相依赖。开始时滚动字幕并先亮红灯，红/蓝每5秒交替。正常播放完成只提交收尾请求；当前轮最长约14.4秒的完整滚动到达边界后，HUB完成回调关闭PC9并同步熄灭两灯。滚动轮次通过计数判断，长语音结束时也不会用历史轮次误判并截断当前画面。启动失败、命令拒绝、轮询异常、手动停止和紧急打断立即关闭屏幕和两灯。若上一轮尚在收尾时启动新的VTX播报，先终止旧指示并从头启动新一轮。播放器忙导致的新请求被拒绝时不操作当前指示。HUB仍以私有5ms定时器完成行扫描，LED以100ms定时器累计5秒交替节拍，两者共享业务完成事件而不混用硬件刷新周期。下一步需要板测完整滚动、灯光交替、同步熄灭、PC9反复开关及VTX音频是否受影响。
